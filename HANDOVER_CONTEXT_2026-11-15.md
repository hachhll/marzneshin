# Handover Context из сессии `check-vpn` (2026-11-15 18:11 UTC)

Этот документ содержит исторические результаты диагностики серверов, архитектурные договорённости и задачи для перехода на стек `marzneshin` (живые IP и домены заменены плейсхолдерами).

---

## 1. Статус серверов на момент миграции (2026-11-15 17:30–18:05 UTC)

1. **`<LEGACY_BLOCKED_IP>` (`server-fam`, Франкфурт):**
   * **Статус:** Окончательно заблокирован ТСПУ по IP на трансграничном уровне по **всем портам**. Недоступен даже из московского дата-центра.
   * **Решение:** Прямой вход из РФ на этот IP невозможен. Детальный разбор причин блокировки — в файле [`RCA_SERVER_FAM_2026-11-15.md`](./RCA_SERVER_FAM_2026-11-15.md).

2. **`<FRANKFURT_AI_EXIT_IP>` (`server-ai`, SSH порт `22222`, пользователь `stealth`):**
   * **Статус:** Запущен, полностью доступен из РФ и с московского сервера по портам `80`, `443`, `22222`.
   * **Исходная проблема:** Изначально использовал старый стек (`Caddy + Xray`) на домене в зоне `.xyz` и раздачу подписок; требовал перевода на `marzneshin` с доменом вне `.xyz`.
   * **Назначение:** Строго изолированный сервер под **рабочий AI-контур** (не смешивать с массовым/семейным трафиком).

3. **`<FAMILY_EXIT_IP>` (резервный зарубежный сервер):**
   * **Назначение:** Основной кандидат под **отдельный семейный/пользовательский зарубежный выход** после перевода на стек `marzneshin` с собственным независимым доменом.

4. **Транзитный VPS в РФ на `REG.RU` (`<MOSCOW_BRIDGE_IP>`, Москва):**
   * **Назначение:** Точка входа внутри РФ (**каскадный мост**) для устройств в РФ, чтобы мобильный трафик не проходил трансграничные фильтры операторов напрямую.

---

## 2. Зафиксированные архитектурные договорённости

1. **Жёсткое разделение AI-контура и семейного/экспериментального трафика:**
   * Устройства с рабочими AI-аккаунтами работают **всегда через один и тот же выделенный VPN-контур**.
   * Мобильные устройства для экспериментов с другими VPN и семейные устройства должны быть отделены от рабочих AI-аккаунтов и не нагружать IP `server-ai`.
2. **Домашний статический IP:**
   * Используется только для личного входа владельца по SSH.
   * **Не используется** как входной VPN-мост для других пользователей.
3. **Отказ от старого домена `.xyz` (`<LEGACY_ROOT_XYZ_DOMAIN>`):**
   * Из-за компрометации поддомена `.xyz` на ТСПУ старый корневой домен больше не должен использоваться на боевых серверах.

---

## 3. Задачи миграции в `marzneshin` (выполнено в последующих изменениях)

1. **Персистентность `TCPMSS 1360` после ребута в `script.sh`:** реализовано в `/etc/ufw/before.rules` (`ufw-mangle-tcpmss`).
2. **Поддержка каскадного моста (`REG.RU Москва -> Зарубежный Exit`):** реализовано через `--bridge` (VLESS + Reality с разрывом TLS и Zero-Loop `dest: 127.0.0.1:8443`).
3. **Миграция на стек `marzneshin`:** выполнена остановка legacy-сервисов и перевод узла `server-ai` на `Xray + Nginx` (`127.0.0.1:8443`).
